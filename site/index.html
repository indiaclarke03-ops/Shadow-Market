          How the reverse stress test works
          1. The simulator runs 20,000 futures for the rule you chose, recording every uncertain input in each one. It uses the same model and random numbers as the What if? or Proposed rule page.
          2. You set a failure line. The futures that cross it are compared with all futures: how often it happens, how each input’s spread shifts, and the middle of each input across failing futures (the most plausible way it happens).
          3. Failing futures are grouped by the inputs that shift most (k-means clustering) into families: different ways the same failure can happen.
          4. If fewer than 40 futures fail, the page studies the futures that come closest instead, and says so.
          5. This is a conditional reading of a simulation (“given the failure, what was true?”), not a forecast. It is simpler than the analytical multi-tier method in the reverse stress testing research it follows: it can only find causes among the inputs and ranges the model already has.

          Proposed rule · Case 2 · Optical transceivers for AI data centres

          What if the rule changes? Testing a regulation before it exists.

          Case 1 asked what today’s rule misses. This case asks: if a reported US restriction on Chinese optical transceivers arrives, what would it cover, what would it leave out, and what would change for the people building AI data centres? The rule has not been published, so the page runs on reported parameters and illustrative supply figures, and every input says which it is.

          Scenario, not forecast. Anything marked reported has no official text yet. The tool takes no side on whether the rule is warranted.
